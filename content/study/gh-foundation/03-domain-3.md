# [Collaboration Features](https://github.com/Andresmup/github-foundations/blob/main/10_ISSUES/Readme.md)
  * `Issue`: Issue是用于跟踪项目中的任务、改进和bug的工具。任何人都可以创建issue，然后其他人可以评论和添加标签来帮助组织和分类。项目所有者还**可以将issue分配给特定的人员**。
  * `Pull requests`: Pull请求是当你对代码进行更改并希望这些更改被合并到主分支时使用的工具。其他人可以查看你的更改，对其进行评论，并最终决定是否接受你的更改。
  * `Discussions`: Discussions是一个用于项目相关讨论的地方，如提问、分享想法或组织社区活动。它们比issue更加灵活，可以**用于任何需要多人参与的讨论**。
  * Notifications: Notifications是GitHub的通知系统，可以让你知道你关注的项目或issue的最新动态。你可以选择接收所有通知，或者只接收你直接参与或被@的讨论的通知。
  * Gist, Wikis, and GitHub Pages: 
    * `Gist`: Gist是**用于分享代码片段**的工具。它们可以是公开的，也可以是私有的，可以被其他人fork和评论。
    * `Wikis`: Wiki是用于项目文档的工具。**任何人**都可以创建和编辑wiki页面，使其成为一个协作的知识库。
    * `GitHub Pages`: GitHub Pages是用于托管静态网站和项目文档的工具。你可以使用Markdown来编写内容，GitHub会自动将其转换为HTML。
  * `Projects`: Projects是一个**看板式的项目管理工具**，可以帮助你组织issue和pull请求。你**可以创建卡片，将它们分配给列，然后移动它们**来跟踪进度。
  * Actions: Actions是一个持续集成/持续部署（CI/CD）工具，可以自动化你的开发工作流程。你可以创建自定义的工作流，例如自动运行测试，构建和部署你的代码。

## [PR](https://github.com/Andresmup/github-foundations/blob/main/11_PULL_REQUESTS/Readme.md)
* If other collaborators branch the project before a force push, the force push may overwrite commits that collaborators based their work on.
* Code owners are not automatically requested to review draft pull requests.
* You can link Issues to PR so that the state of the pull request will automatically close the issue. - The PR must be on the default branch.
